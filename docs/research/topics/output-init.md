# 出力の重みの初期値

注意と MLP の最後の重み（`c_proj`）の初期値。ここから出た値が残差に足される。`lm_head` の初期値は別の話で、埋め込みの分離と一緒に考える。

- **小さい値：** 基準と最初の束。GPT-2 と同じ 0.02/√(2×層の数) で、10層なら0.0045。
- **0：** 学習の始めは、各層が入力をそのまま通す。[nanochat](../sources/nanochat-log.md)、[autoresearch](../sources/autoresearch.md)、[modded-nanogpt](../sources/modded-nanogpt-records.md) はどれもこの形で、どれも Muon で動いている。どれも単独の効果は測っていない。
- **縮小なしの0.02：** HF の Llama の既定。

## 分かっていること

今の小さい値と0を直接比べた結果は見つけていない。近い比較は次の通り。損失の差は自分たちの計算。

| 出典 | 条件 | 比べたもの | 結果 |
|---|---|---|---|
| [Multi-Head Low-Rank Attention](../sources/multi-head-low-rank-attention.md) | 29億、AdamW、983億トークン | 0.02 から0 | −0.63%。9つの注意の形のうち8つで良い（+0.06%〜−1.30%） |
| [Optimal Scaling](../sources/optimal-scaling-norm.md) | 幅256、2〜64層、Scion、2.7億トークン | 縮小なしから 1/√(2×層の数) | −0.24%〜−0.55%。著者は無視できるくらいとしている |
| [Physics of LM 4.1](../sources/physics-of-language-models-4-1.md) | Llama など | 1/√N から縮小なし | 縮小なしが「わずかに良い」。数字なし |
| [μ-Transfer](../sources/mu-transfer.md) | 最大12億、Adam | Q の重みを0から | −0.04%〜−0.14% |
| [ReZero](../sources/rezero.md) | 12層、1文字ずつ、LayerNorm なし | 層全体に掛ける値を1から0へ | BPB 1.2 までの回数が約0.6倍。最後の BPB は同じ |
| [LayerScale](../sources/layerscale.md) | 画像、12〜36層 | 層全体に掛ける値を0から小さい値へ | 小さい値が良い。12層で精度 78.3 から 80.4 |

[SkipInit](../sources/skipinit.md) は画像の CNN で、1/√深さ と0がほぼ同じ。[Transformers Are Born Biased](../sources/born-biased.md) は、ランダムな初期値がトークンの好みの偏りを生み、学習のあとも弱く残るとしている。0ならこの偏りは始めに出ないはずだが、これは自分たちの読みで、品質への影響は分からない。

**今の値からの差は小さいはず：** −0.63% の相手は今の値の約4.5倍大きい。Muon の更新の大きさは勾配によらず1回0.04で、MLP の出力の重みの初期の大きさ（特異値で0.11〜0.34）には3〜9回で追いつく（自分たちの計算）。

**費用：** 計算は変わらない。重みも増えない。

**Muon で動くか：** 最初の更新では、出力の手前の重みの勾配が0になる。今の Muon はこのとき更新が0になるだけで、次の更新から動く（`muon.py` を読み、テストでも確かめた）。

**最初の損失：** 埋め込みを共有したまま0から始めると、最初の損失が高い。入力がそのまま出力に届き、同じトークンを強く予測するため。2番目の束の形（幅640、埋め込みの標準偏差0.02）で試すと、最初の損失は今の値の9.1に対して12.8。本来の約500分の1のバッチで学習すると、2回目の更新で8.2まで下がり、そのあとの30回では今の値と差が見えなかった。modded-nanogpt の記録5（幅768）も16.0から2回目に9.5へ下がる。これは出だしの確認で、品質の比較ではない。

## 今の見方

2026-11時点の見方では、次の束は0にする。同じお金での効果は0〜0.3%と小さく見ている。理由は次の通り。

- 費用がなく、1行の変更で、重みも増えない。
- 束は測るのが1回なので、Muon で動いた例に揃える。autoresearch の学習率の組も、この形で動いている。
- 言語モデルで0が悪くなった報告は見つけていない。

ほかの形は選ばなかった。層全体に掛ける値（ReZero、LayerScale）は今の形に近い比較がなく、近い案の x0、resid の重みで別に考える。CompleteP は Optimal Scaling の比較で、掛けない形より悪い（+1.5〜2.4%）。

## 見方が変わりそうな条件

- 今の値と0を直接比べた結果が出た場合。
- 効果を項目ごとに測った場合。
- 学習率を大きく変えた場合。0で動いた組から離れると、例に揃える理由が弱くなる。
