# 速度と費用

同じお金で読めるトークンを増やす候補。目的が同じお金で良いモデルを作ることなので、モデルの改善と同じ扱いにする。2026-11時点の見積もりで、改善を測った結果ではない。

効果は、計算量2倍で loss が約3.9%下がるという換算（Delphi の式、[Marin の記事](../sources/marin-moe.md)）で出した粗い値。

## 基準の学習の時間の使い方

内訳は[基準の学習](../experiments/baseline.md)にある。1回の貸出のうち学習は約68%で、残りの大半は借りてから使えるまでとデータの転送。GPU の使用率は学習中99〜100%なので、データの読み込みは詰まりではなかった。

効率は、autoresearch と同じ式（6N + 12·L·H·Q·T、H100 の bf16 のピーク989.5 TFLOPs）で約40%。autoresearch の表示は39.8%、nanochat の LOG は約46%。nanoGPT の表示は A100 が基準で、そのまま比べられない。

## 候補

| 候補 | 効果の見込み | 注意 |
|---|---|---|
| 料金（[Vast の料金](../experiments/gpu-prices.md)） | 借りた $2.41/時が最安の $1.74 になれば約1.8%、半額なら3.9% | 最安の機械はドライバが古い。モデルは変わらない |
| 中断ありの貸出 | 約65%安いので最大5.9% | `language-model` の [メモ](https://github.com/tomato414941/language-model/blob/main/docs/research/topics/interruptible-gpu.md)では、H100 は1分で止まって戻らなかった |
| 準備の時間 | 100秒まで縮めば約1.6% | 連続で回せば小さくなる。大規模には関係しない |
| 注意の計算の方式（attention-kernel.md） | 不明 | 基準の PyTorch は既定で cuDNN を使うはずで、FlashAttention-2 と比べた数字は当てはまらない。式の上では計算の18%が注意で、実時間の割合は分かっていない |
| 効率全体 | 46%まで上がれば約0.8% | 差の原因は未調査 |
| 1回に流す本数 | 不明 | メモリは80GBのうち約28GB で余裕がある。短い計測で確かめられる |
| FP8 | 今の規模では0か損 | `language-model` の [メモ](https://github.com/tomato414941/language-model/blob/main/docs/research/topics/fp8.md)では、26層で1.17倍速いが同じ損失では約5%、12層ではかえって遅い |

[Auto Research](../sources/auto-research.md) では、nanochat の品質スコアが38.7%上がり、最も大きく伸びたのは、速度の無駄を見つけて浮いた時間をトークンに回した変更だった。速度は学習を最後まで回さなくても測れるので、モデルの比較より安く確かめられる。

## 分けて考えること

- 大規模でも効く：注意の計算、効率、GPU の選び方。
- 小さい規模でだけ効く：準備の時間。研究の費用は減るが、フロンティアに通じる改善ではない。
- モデルは変わらない：料金。学習量は増えるが、モデルや学習法の改善そのものではない。

## 見方が変わりそうな条件

- H100 で時間の使い方を測り、今の見積もりと違った場合。
- 料金が大きく変わった場合、借りられる GPU が変わった場合。
