# Composer

Composer: A Search Framework for Hybrid Neural Architecture Design（arXiv 2510.00379、ICLR 2026）。注意（A）と MLP（M）の並べ方を小さいモデルで探し、大きくして同じ幅の Llama 3.2 と比べる。

## 条件

- 幅は Llama 3.2 と同じ（10億は2,048と8,192、ヘッド32、KV ヘッド8）。層は Llama 3.2 の32（16ブロック）より少なく、重ねる形が27、伸ばす形が29（§4.2）。パラメータの数の揃え方は書かれていない。
- 6層の探索で見つかった形は 2A+4M（§4）。数だけの書き方で、注意と MLP の順番は書かれていない。同じ種類は続けて並べる（§2.4）。
- 10億の形は、重ねる形が 4×(2A+4M)+1A+2M、伸ばす形が 4A+9M+4A+5M+2A+5M（付録 B.1）。
- 10億の比較は375億トークンで、1パラメータ約37トークン（付録 C.5）。

## 結果

- 10億（Table 2）：Llama 3.2 は損失 2.80、点の平均 58.69。重ねる形は 2.77、60.83。伸ばす形は 2.77、60.76。
- 点の平均（Table 6）：3.5億では Llama 3.2 の 55.4 に対し、重ねる形 56.0、伸ばす形 56.7。30億では 59.2 に対し 61.0、62.0。小さいモデルほど差が小さい。
- 幅を狭めずに1億〜2億パラメータで探すと、一番良い形は 3A+3M（1対1）だった。1対2 は幅を狭めた探索で見つかり、大きくしたときに1対1より良かった（§3.3）。比率だけを変えた比較の数字はない。
- 学習は約1.25倍、推論は約1.33倍速く、KV キャッシュは約1.69分の1になる。

読んだのは arXiv の HTML 版の §2.4、§3.1〜3.3、§4.2、Table 2、6、付録 B.1、B.4、B.5、C.5 の該当部分（ツールで抜き出した要約と引用から）。
