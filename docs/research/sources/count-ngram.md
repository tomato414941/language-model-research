# COUNT

Magnusson、Smith、Koh（arXiv 2610.20456、2026-10）。結果の全体は `language-model` の [メモ](https://github.com/tomato414941/language-model/blob/main/docs/research/sources/count-ngram.md)にあり、ここにはそこにない内容だけを書く。

## 仕組み

- 凍結した表が、各 n-gram の履歴に対して、続くトークンの上位 K 個と点数を持つ。点数は stupid backoff（見た続きは回数の比、なければ短い履歴に戻って0.4倍）。
- 入力は `f_t = (1/J) Σ_j Σ_k S(w_k | h_{t,j}) B[w_k]` で、B はモデル自身の出力の表。最初の層への入力は `f_t + e_t`。
- 学習では K=8、J=6（1〜6トークン）。B に勾配が流れるかは、読んだ範囲に書かれていない。
- 表はメインのメモリに置き、先読みと速い検索で GPU の計算の後ろに隠す。

## そのほかの数字

- 比べた相手は Over-Encoding（学習する2、3トークンの表を GPU に置く）。パラメータの総数で見た最良の線はほぼ COUNT が占める。190M の学習する表は、表全部を更新すると普通の形の4.4%の速さ、触った行だけなら96.3%。
- 数式の 6ND に、出力の表の行を集める計算は入っていない。
- 分野を絞った表（数学、医学、法律）を推論の時に混ぜると、その分野の課題の損失は下がり、点は分かれた。
- 著者も、高い次数の珍しい文脈では、表が元の文章の断片を漏らしうるとしている。
- 実験は 1B までで、コーパスは Dolma 3 だけ。計数にかかった時間は書かれていない。
